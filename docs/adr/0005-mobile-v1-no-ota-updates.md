# ADR-0005 · 앱 1차는 원격 업데이트(EAS Update) 없이 낸다

- 상태: 채택 · 2026-09-14

## 배경
ADR-0001은 Expo를 고른 이유로 「EAS Update로 JS 수정을 심사 없이 배포할 수 있다」를 꼽았다. 세법은 매년 바뀌니, 룰셋을 고칠 때마다 스토어 심사를 거치지 않아도 되면 편하다.
그런데 `expo-updates`는 앱을 켤 때 업데이트 서버에 요청을 보낸다. ADR-0003은 「서버·네트워크 없음」이고, 스토어 개인정보 항목도 그 전제로 「수집 없음」이다.

## 결정
v0.1은 `expo-updates`를 넣지 않는다. 룰셋 변경은 새 버전을 만들어 스토어 심사를 거쳐 낸다.

## 이유
- 앱이 네트워크를 쓰지 않는다는 약속을 코드와 스토어 표기 양쪽에서 지킨다
- 룰셋은 1년에 한두 번 바뀐다. 이 빈도면 스토어 업데이트(심사 보통 하루 이틀)로 충분하다
- 네이티브 모듈·런타임 버전·업데이트 채널을 관리할 필요가 없다

## 대안과 버린 이유
- 켤 때마다 확인(`checkAutomatically: ON_LOAD`): 매 실행이 네트워크 요청이다. ADR-0003과 정면으로 부딪힌다
- 수동 확인 버튼만 두기: 요청은 사용자가 누를 때만 나가지만, 그래도 네트워크 권한·개인정보 표기·서버 운영이 생긴다. 1년에 한두 번을 위해서는 과하다

## 결과
- 세법이 바뀌면(예: 2027-01-01 시행 세법) `packages/tax-engine/src/rules.ts`를 고치고 새 빌드를 스토어에 낸다
- `expo-updates`는 나중에 넣더라도 새 네이티브 빌드가 필요하다. 넣게 되면 이 ADR을 대체하는 ADR을 쓰고, 개인정보처리방침과 스토어 개인정보 항목을 함께 고친다
